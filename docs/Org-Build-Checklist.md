## Agentforce: what exists in the product (names to use)

Salesforce evolves APIs quickly; always confirm in **Setup** and the [Agentforce Developer Guide](https://developer.salesforce.com/docs/ai/agentforce/guide/agent-overview.html) for your org’s edition.

### Builder UI (what you click in Setup)


| UI area                                                            | Purpose                                                                                                           |
| ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| **Agents** (Einstein / Agentforce **Service Agent** or equivalent) | One conversational agent for the patient “digital front door.”                                                    |
| **Agent instructions** (global / system)                           | Scope, tone, safety, verification rules (short; see best practices).                                              |
| **Topics**                                                         | Route intents (locations, book, cancel, insurance, …) to the right **actions** and instructions.                  |
| **Actions**                                                        | Call **Flow** (autolaunched), **Apex** (`@InvocableMethod`), **REST**, **prompt templates**, or packaged actions. |
| **Data library / Knowledge** (when available)                      | Ground answers on `Knowledge__kav` and other vetted sources.                                                      |
| **Channels**                                                       | Experience Cloud, Messaging (web/WhatsApp), etc.                                                                  |
| **Testing / Preview**                                              | Validate tool calls and refusals before go-live.                                                                  |


### Metadata API (source-driven / DX deploy)

Use the [Agents metadata reference](https://developer.salesforce.com/docs/ai/agentforce/references/agents-metadata-tooling/agents-metadata.html) for the exact types your org supports. Common patterns (names vary by API version):


| Metadata (typical)          | Maps to                                                                              |
| --------------------------- | ------------------------------------------------------------------------------------ |
| `**GenAiPlannerBundle`**    | Planner + agent configuration (reasoning / orchestration container).                 |
| `**GenAiPlugin`**           | **Topic** (subagent / scoped instruction + action references).                       |
| `**GenAiFunction`**         | **Agent action** wrapping an invocable Flow, Apex, etc.                              |
| `**Bot`**, `**BotVersion`** | Alternate or legacy packaging for conversational agents (some orgs still show this). |
| `**AiAuthoringBundle**`     | Agent DX / blueprint-style packaging (newer authoring flows).                        |


**Deploy order (best practice):** underlying **Flow** or **Apex** → `**GenAiFunction`** (action) → `**GenAiPlugin`** (topic) → `**GenAiPlannerBundle**` / agent container → channel binding.

## Best practices (public guidance — apply while you build)

1. **Narrow scope** — One primary job per agent (scheduling + navigation), not “everything about cancer.” ([Implementation discipline](https://www.salesforce.com/blog/ai-implementation-pitfalls/))
2. **Short instructions** — Put procedures in **Knowledge** and **actions**, not megabyte global prompts. Avoid huge lists of “never do X.” Prefer **positive** scope (“You only help with …”). ([Salesforce AI pitfalls blog](https://www.salesforce.com/blog/ai-implementation-pitfalls/))
3. **Grounding over hallucination** — Prefer **SOQL via Flow actions** and **Knowledge articles** over asking the model to invent facility or clinical facts. ([Agentforce actions guide](https://developer.salesforce.com/docs/einstein/genai/guide/get-started-actions.html))
4. **Data quality** — Seed facilities/specialties/providers consistently with Knowledge names.
5. **Least privilege** — **Integration / Einstein Agent** user + **Experience Guest** profile: only objects/fields/flows needed for each script. Use `**Hackathon_Data_Model_Access`** (or a **site-specific** permission set) deliberately.
6. **Observability** — Log tool runs to `**Agent_Action_Log__c`** (no PHI in free text).
7. **Failure UX** — Test **no match / multi-match phone**, **no slots**, **invalid picklist** (scripts §18–21).
8. **Version & sandbox** — Build in sandbox; document active **agent version** for demo.
9. **Licensing / credits** — Confirm **Agentforce / Einstein** entitlements and conversation or **Flex Credit** model for demo org ([planning guides](https://developer.salesforce.com/docs/ai/agentforce/guide/agent-overview.html)).
10. **Reasoning engine** — Product may reference **Atlas** (or successor) for planning; behavior is configured via topics + actions, not custom code.

## Experience Cloud + Embedded Messaging (follow this order in Setup)

Operational sequence aligned with [How to Set Up Salesforce Agentforce on an Experience Cloud Site](https://medium.com/@tushardangayach/how-to-set-up-salesforce-agentforce-on-an-experience-cloud-site-step-by-step-guide-4e0ca0a8374b) (Embedded Messaging → Omni-Channel → Experience Builder). **Live site:** [https://orgfarm-ebac756354.my.site.com/oncoglobalcare/](https://orgfarm-ebac756354.my.site.com/oncoglobalcare/). | Step   | Setup path                                                                     | What to do (Onco mapping)                                                                                                                                                                                                                                         |
| ------ | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1**  | **Setup → Einstein Setup**                                                     | Turn **Einstein** on (prerequisite for Agentforce).                                                                                                                                                                                                               |
| **2**  | **Setup → Agentforce Agents**                                                  | Ensure **Agentforce** is enabled → **New Agent** → type **Service Agent**. Set name/description; link **Agent User** (e.g. **Einstein Service Agent** user) with `**Hackathon_Agent_Runtime_Access`** / `**Onco_Global_*`** permission sets so HC Flows/Apex run. |
| **3**  | **Agent Builder** (open agent from step 2)                                     | **Topics** + instructions for patient scheduling/navigation per `**docs/Patient-Agent-Conversation-Scripts.md`** and `**docs/Agentforce-Subagents-Design.md`**. Wire **actions** to `**HC_*`** flows and `**HC_*` invocables** (checklist rows 20–22).            |
| **4**  | **Setup → Messaging Settings**; **Setup → Omni-Channel Settings**              | Turn **Messaging** ON; turn **Omni-Channel** ON.                                                                                                                                                                                                                  |
| **5**  | **Setup → Routing Configurations → New**                                       | Create a config: **Routing Model** (e.g. Most Available), **Units of Capacity** as needed; rest default unless your org prescribes otherwise.                                                                                                                     |

In the component sidebar, select the **Embedded Service Deployment** from step 9. **Publish** the site. **Do not** expect the full chat to work inside Builder — test on the **published** URL.          |
| **11** | Published site URL                                                             | Hard-refresh (or incognito). Open the widget; run `**Patient-Agent-Conversation-Scripts.md`** paths; if no agent reply, verify routing flow **Active**, channel **Omni-Flow**, and agent user **permissions**.                                                    |


**Troubleshooting (from the same guide):** Widget missing → deployment **Published** and component **deployment** selected. No replies → topics/actions + routing flow. Wrong answers → topic instructions + data access (least privilege).
